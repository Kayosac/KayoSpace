# 0014. Хаб на сервере обновляется сам — по релизам

- Статус: принято
- Дата: 2026-11-05

## Контекст

Чтобы обновить хаб, нужно было зайти на сервер по SSH и повторить команду установки.
Приложения уже обновляются сами (решение 0011), хаб отставал.

## Решение

- Хаб следует за **релизами** (`vX.Y.Z`), а не за main: версии хаба и приложений совпадают,
  а выпуск по-прежнему одно действие.
- `setup.sh` ставит последний релиз (ветку — по `BRANCH`, например `BRANCH=main`) и systemd-таймер
  `kayospace-update.timer`: через 5 минут после загрузки и дальше раз в 10 минут запускается
  `/usr/local/sbin/kayospace-update` (копия `deploy/update.sh`). `AUTO_UPDATE=0` — без таймера.
- `update.sh`:
  1. узнаёт последний релиз через API GitHub (публичный репозиторий, без ключей; лимит 60 запросов
     в час, а нужно 6);
  2. если он уже стоит (`deploy/.deployed`) или уже не поднялся (`deploy/.failed`) — выходит;
  3. иначе берёт код релиза, выполняет `docker compose up -d --build` (пока собирается образ, работает
     прежний хаб) и ждёт `/health` до 3 минут;
  4. не ответил — откатывается на прежний код, пересобирает его и запоминает неудачный релиз,
     чтобы не пересобирать его каждые 10 минут. Следующий релиз пробует снова.
- Два запуска одновременно не идут (`flock`). Журнал — `journalctl -u kayospace-update`.
- Скрипт проверяется тестом с заглушками curl, git и docker (`server/hub/src/deploy-update.test.ts`).

## Последствия

- Хаб на сервере переходит на новый релиз в течение ~10 минут после его выхода; перерыв — секунды
  на перезапуск контейнера.
- Неудачный релиз откатывается сам, но исправить его можно только новым релизом.
- Чтобы включить автообновление на уже работающем сервере, один раз нужно повторить команду установки.
