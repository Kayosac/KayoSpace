# 0005. Хаб на VPS раньше плана: Docker, Caddy, токен, sslip.io

- Статус: принято
- Дата: 2026-11-04

## Контекст

Проверка синхронизации планшет ↔ мак упёрлась в домашнюю сеть: устройства не видят друг друга из-за настроек
роутера. Хаб на VPS по плану был в фазе 2–3; переносим его вперёд, потому что он снимает зависимость от
домашней сети и всё равно нужен для агентов.

## Решение

- **Доступ по токену** (`HUB_TOKEN`). Синхронизация: `?token=` в адресе WebSocket (браузерный WebSocket
  не умеет заголовки); при неверном токене хаб закрывает соединение с кодом 4401, клиент перестаёт
  переподключаться и показывает «неверный токен». REST и MCP: `Authorization: Bearer`. MCP дополнительно
  проверяет Host и Origin (защита от DNS rebinding). Сравнение токенов — за постоянное время.
- **HTTPS** — Caddy перед хабом, сертификат Let's Encrypt выпускается и продлевается автоматически.
- **Адрес без домена** — `<IP через дефисы>.sslip.io`: публичный DNS, который отвечает IP из имени.
  Свой домен подключается переменной `HUB_DOMAIN`.
- **Развёртывание** — `deploy/setup.sh` одной командой на свежем Ubuntu: Docker, код, `.env` с токеном,
  `docker compose up`. Повторный запуск — обновление. Образ проверяется в CI (сборка, запуск, доступ по токену).
- **Клиент** — таймаут подключения 8 секунд и причина в интерфейсе (хаб не отвечает, неверный токен,
  соединение закрылось) вместо бесконечного «подключаюсь».

## Последствия

- Без токена хаб по-прежнему работает локально (MCP — только с localhost) — для разработки.
- Один токен на всё — достаточно для одного человека. Токены на устройство и OAuth для ChatGPT и claude.ai —
  фаза 3.
- Резервные копии пока вручную (команда в `deploy/README.md`); автоматические — фаза 2.
