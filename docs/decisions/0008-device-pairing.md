# 0008. Подключение устройств по коду, токен на устройство, режим разработки

- Статус: принято
- Дата: 2026-11-04

## Контекст

Чтобы подключить планшет или мак, приходилось вручную вводить адрес хаба и общий `HUB_TOKEN` — длинную
случайную строку. Один токен на всё нельзя отозвать у одного устройства, а хранился он в `localStorage`.
Для разработки нужно было отдельно запускать хаб и вписывать его адрес в настройки.

## Решение

**Код подключения.** Подключённое устройство (Настройки → Устройства → «+ Добавить») или администратор
(`docker compose exec hub pnpm pair` на сервере, `pnpm pair` локально) получает от хаба код: 6 цифр,
одноразовый, живёт 5 минут. Вместе с ним — ссылка `kayospace://connect?hub=<адрес>&code=<код>` в QR.
Новое устройство отдаёт код (`POST /api/devices/claim`) и получает **свой** долгоживущий токен
`kd_<id>_<секрет>`.

- Перебор: каждая неверная попытка засчитывается всем действующим кодам, после 5 они сгорают;
  плюс не больше 10 попыток в минуту с адреса (за Caddy — адрес из `X-Forwarded-For`).
  Вероятность угадать код — не больше 5 из миллиона.
- На хабе — только SHA-256 секрета (`data/devices.json`), сравнение за постоянное время.
- На устройстве — хранилище ОС: Keychain (macOS), Credential Manager (Windows), Android Keystore
  (AES-256-GCM, ключ не покидает Keystore). Свой плагин Tauri `secure-store`: десктоп — крейт `keyring`,
  Android — небольшой Kotlin-класс. Готовый плагин для всех трёх ОС слишком молодой (0.2.0).
  В браузере (разработка, проверки) — `localStorage`.
- «Отключить» удаляет запись: REST сразу отвечает 401, открытые WebSocket этого устройства закрываются
  кодом 4401, приложение показывает экран подключения с причиной.
- Список устройств: имя, платформа, дата последнего входа (обновляется не чаще раза в минуту).

**QR.** Системная камера открывает ссылку `kayospace://` (плагин deep-link, на Windows — вместе
с single-instance, чтобы ссылка ушла в уже открытое окно). На Android есть и сканер внутри приложения
(официальный плагин barcode-scanner): не все камеры открывают нестандартные схемы ссылок.

**HUB_TOKEN остаётся ключом администратора**: им входят коннектор Claude (страница OAuth), Claude Code,
исполнитель ИИ и `pnpm pair`; он же — способ вернуть доступ, если отключены все устройства.
На устройствах он больше не нужен. Старые настройки с `HUB_TOKEN` при первом запуске сами меняются
на токен устройства (`POST /api/devices/register`, только с ключом администратора) — переподключать
ничего не надо. Хаб старой версии (нет `/api/devices`) — приложение пока работает по старому токену.

**Адрес хаба по умолчанию** на экране подключения задаётся при сборке (`VITE_DEFAULT_HUB`, в GitHub Actions —
переменная репозитория `KAYOSPACE_DEFAULT_HUB`), в коде его нет. Если он задан, при первом запуске
приложение сразу предлагает подключиться.

**Режим разработки.** `pnpm dev` (scripts/dev.mjs) поднимает хаб на `127.0.0.1` без токена (данные — `.dev-hub/`)
и передаёт его адрес приложению в `VITE_DEV_HUB`; приложение подключается само, доски и настройки хранятся
под отдельным префиксом. Ветка включается только при `import.meta.env.DEV` и не-production режиме —
в сборке Vite вырезает её целиком (это проверяет тест `build.test.ts`). `tauri android dev` хаб не поднимает:
планшет не достучится до 127.0.0.1 компьютера.

## Последствия

- Хаб без токена (локальный) открыт как раньше, но отозванный токен устройства не проходит и там.
- Устройства не видят чужие токены и не могут выдать токен без кода (`register` — только администратору).
- Сборку Android-плагина `secure-store` проверяет только CI-сборка приложения (`app.yml`): локально нужен Android SDK.
- Код и ссылка не защищены от того, кто видит экран в эти 5 минут, — как и любой код подключения.
