# План Kayospace

Полная версия с разбором задачи, схемами и рисками — в документе
[Workspace: разбор задачи и план реализации](https://claude.ai/artifact/JC9HoNgzkQKdEEe8FcA4RF).
Здесь — короткая выжимка, чтобы она была под рукой у Claude Code.

## Решено (4 ноября 2026)

- Основное устройство для пера — Android-планшет.
- Хаб (синхронизация + MCP для агентов) — на своём VPS.
- Код пишет в основном Claude Code.
- Движок холста — свой.
- Рабочее имя — Kayospace.

## Архитектура

Клиенты (macOS, Windows, Android на Tauri 2; браузер) работают на общем веб-ядре и хранят полные локальные копии досок.
Хаб на VPS синхронизирует Yjs-документы, хранит файлы, ищет, рендерит доски в PNG и отдаёт всё агентам через MCP.
Claude Code подключается по MCP (stdio или HTTP) и дополнительно читает зеркало досок в Markdown.

## Модель данных

Воркспейс → Проект → Доска → Элемент. Одна доска — один Yjs-документ. Типы элементов:
`stroke`, `text`, `sticky`, `image`, `frame`, `arrow`, `shape`. Штрихи хранятся бинарно (`packages/model/src/stroke-codec.ts`).
У каждого элемента есть `createdBy`/`updatedBy` с пометкой «человек / агент».
